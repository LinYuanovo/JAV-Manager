# 项目：本地视频媒体管理器（Windows 版）

使用 Flutter 开发一个 Windows 桌面应用，功能类似 Kodi，用于管理本地视频媒体库。UI 风格需具备以下特点：
- 玻璃拟态（毛玻璃效果）、呼吸感、圆润平滑自然
- 大量使用圆角、半透明、柔和阴影、渐变和流畅动画
- 整体 UI 精致现代，参考 macOS / Windows 11 设计语言

## 核心架构要求
- 状态管理：推荐使用 Riverpod 或 Provider
- 本地数据库：SQLite（使用 `sqflite` 或 `drift`）
- 文件操作：使用 `path_provider` 和 `dart:io`
- 网络请求：使用 `http` 或 `dio`
- HTML 解析：使用 `html` 包（解析 Wikipedia）
- 缓存：使用内存缓存 + 磁盘缓存（如 `cached_network_image`）
- 自动任务：使用 `Timer.periodic` 实现定期扫描和移动

## 页面布局（侧边栏导航）
左侧固定侧边栏（可折叠），包含菜单项：
- 媒体
- 演员
- 分类
- 收藏
- 已观看
- 设置

点击菜单项切换右侧内容区域。

# 模块详细设计

## 1. 媒体模块
展示本地视频文件，数据来源于指定目录扫描。

### 数据来源
- 从本地媒体库目录读取，目录结构：
媒体库根目录/
├─#整理完成/
│ ├─女优名1/
│ │ ├─[番号] MIDA-280/
│ │ │ ├─fanart.jpg (海报墙背景)
│ │ │ ├─MIDA-280-U.mp4
│ │ │ ├─MIDA-280-U.srt
│ │ │ ├─movie.nfo (视频元数据)
│ │ │ └─poster.jpg (海报)
│ ├─女优名2,女优名3/ （多演员逗号分隔）
│ │ ├─[番号] ...
├─Watched/ （已观看影片自动移入）
│ ├─女优名/
│ │ ├─[番号] ...

### 影片属性解析
从 `movie.nfo` 中提取：
- `title`：影片标题
- `actor`下的`name`：演员名（可能有多个）
- `tag`：标签
- `set`：系列
- `studio`：片商
- 其他元数据

### 排列方式（可选切换）
- 列表
- 海报图（纯图片网格）
- 带标题的海报图（图片+标题）
- 海报墙（使用 fanart.jpg 做大图背景，叠加信息）

除列表模式外，默认根据窗口宽度自适应列数；提供开关“固定每行数量”，开启后用户可设定列数，优先级更高。

### 网格模式增强
- 右上角显示收藏按钮（心形/星形）
- 若影片已观看过，左上角显示“已看”图标（如眼睛）

### 排序方式
- 标题（A-Z / Z-A）
- 随机
- 最近观看（最近播放时间，顺序/倒序）

### 刷新
提供刷新按钮，手动触发重新扫描媒体库并更新 UI。

## 2. 演员模块
列出本地所有演员（从 `movie.nfo` 的 `actor/name` 提取，去重）。

### 网格展示
- 网格形式显示演员头像和姓名
- 头像获取：从 GitHub 仓库 `https://github.com/gfriends/gfriends` 获取，命名规则为演员名（需确认路径结构，可能为 `演员名.jpg` 或子目录）

### 详情页
点击演员进入：
- 显示演员详细信息，通过解析 Wikipedia 获取：
- 请求 `https://ja.wikipedia.org/wiki/演员名`
- 解析 HTML 提取：
  - 出生月日：`[title="誕生日"]`
  - 身高：`[title="身長"]`
  - 体重：`[title="体重"]`
  - 三围：`[title="スリーサイズ"]`
  - 罩杯：`th:contains("ブラサイズ")`
- 下方展示该演员出演的本地影片（网格/列表）

### 排序与收藏
- 排序方式：名称、本地影片数量（升序/降序）
- 右上角收藏按钮，收藏的演员优先显示在最前

---

## 3. 分类模块
分为三个子视图：标签、系列、片商

### 数据来源
- 标签：`movie.nfo` 中的 `tag`
- 系列：`movie.nfo` 中的 `set`
- 片商：`movie.nfo` 中的 `studio`

所有分类项首次扫描时存入 SQLite，即使本地视频删除也不删除分类记录。若繁体中文自动转换为简体中文再存储，避免重复。

### 展示
- 每个子视图用网格/列表显示分类项
- 根据该分类项是否仍有本地视频，用不同颜色或状态区分（例如有视频高亮，无视频置灰）

### 交互
- 点击分类项，展示包含该标签/系列/片商的影片
- 支持收藏分类项（具体到标签/系列/片商），收藏后可在“收藏”模块查看

## 4. 收藏模块
集中展示用户收藏的内容，包括：
- 影片
- 分类（点击后进入对应子类选择）
- 演员

采用 tab 或分段控件切换。

## 5. 已观看模块
展示已观看的影片列表，观看次数和最近观看时间在数据库中即时记录。

- 点击影片时，调用系统播放器播放，并更新观看次数和最后观看时间。
- 显示观看次数和观看时间。

---

## 6. 设置模块
提供配置项：
- 媒体库目录：选择本地媒体库根目录（即包含 `#整理完成` 的目录）
- 播放器路径：可选，填写外部播放器可执行文件路径，为空则使用系统默认播放器
- 已观看影片目录：默认为媒体库根目录下的 `Watched`，可自定义
- 自动扫描间隔：设定每隔多少分钟自动扫描并移动已观看视频（默认5分钟）

### 自动整理逻辑
每 N 分钟执行一次后台任务：
1. 扫描数据库中观看次数 >= 1 的视频
2. 将视频所在的 `[番号] 文件夹` 及其所有内容移动到“已观看影片目录”下，保持原有演员名父目录结构
3. 刷新媒体库文件索引，更新 UI

# 数据库设计（SQLite）
需要以下表（示例，可根据实现调整）：

1. **videos**
 - id (INTEGER PRIMARY KEY)
 - file_path (TEXT UNIQUE)   // 视频文件绝对路径
 - folder_path (TEXT)        // [番号] 文件夹路径
 - title (TEXT)
 - poster_path (TEXT)
 - fanart_path (TEXT)
 - nfo_path (TEXT)
 - watch_count (INTEGER DEFAULT 0)
 - last_watched_time (DATETIME)
 - is_favorite (INTEGER DEFAULT 0)
 - created_at, updated_at

2. **actors**
 - id
 - name (TEXT UNIQUE)
 - avatar_url (TEXT)
 - is_favorite (INTEGER DEFAULT 0)
 - info_json (TEXT)  // 存储 Wikipedia 解析结果 JSON

3. **video_actors** (多对多)
 - video_id
 - actor_id

4. **tags / series / studios** 可统一为 `categories` 表：
 - id
 - type (tag/series/studio)
 - name (TEXT)
 - is_favorite (INTEGER DEFAULT 0)
 以及多对多关联表 `video_categories`。

5. **play_history** (可选，用于更细粒度的观看记录)

- 重要：演员信息、分类项（标签/系列/片商）即使相关视频被删除，也不删除记录，仅通过是否存在关联视频来判断状态。

# 通用技术要求
- 充分复用组件（例如影片卡片组件、网格列表组件、演员头像组件）
- 使用缓存策略：
- 影片海报/演员头像使用 `cached_network_image` 或本地文件缓存
- 数据库查询结果在内存中缓存，避免重复查询
- 所有文件扫描逻辑放入 isolate 或异步处理，避免阻塞 UI
- 界面适配不同窗口大小，支持响应式布局
- 动画和过渡自然，符合“呼吸感”
